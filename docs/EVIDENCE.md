# 시연 증거 — 승격 · 롤백 · 탈락 실행 기록

2026-11-23 에 GitHub Actions 에서 실제로 돌린 실행의 링크와 로그 발췌다. 요건별로 무엇을 보여 주는지는 [PLAN.md](PLAN.md) 의 요건 점검표에 있다.
`/health` 응답은 서버 러너가 실행 로그에 찍은 것을 그대로 옮겼다 (서버 주소는 적지 않는다).

화면 캡처는 아직 없다. 저장소가 비공개라 로그인한 브라우저에서 아래 링크를 열어 직접 찍어야 한다.

## 2. 두 번째 승격 — 현재 모델 검사가 돈다

store 가 서비스 중인 모델을 버킷에서 꺼내 train 에 넘겼고, 게이트의 세 번째 검사가 돌았다.

```
현재 모델 m20261123-2 → artifacts/current
기준선 검사: 모델 0.6980  기준선 0.6994  (허용 0.7094 이하)
현재 모델 검사: 모델 0.6980  현재(m20261123-2) 0.6980  (허용 0.7030 이하)
게이트 통과
parity: 200행, 확률 차이 최대 4.92e-08 (기준 1e-04 이하)
{"status":"ok","app_version":"v0.1.0","model_version":"m20261123-3"}
포인터: m20261123-2 → m20261123-3
```

같은 데이터로 다시 학습했으므로 두 모델의 점수는 같다.

## 3. 롤백 — 요건 5

```
{"status":"ok","app_version":"v0.1.0","model_version":"m20261123-2"}
포인터: m20261123-3 → m20261123-2
포인터: m20261123-2  이전: m20261123-3  바꾼 때: 2026-11-23T04:59:16Z
```

학습 · 검사 없이 버킷에 있던 버전을 다시 띄웠고, 이미지(`v0.1.0`)는 그대로다. 시작부터 끝까지 1분이 걸리지 않았다.

## 4. 게이트 탈락 — promote 가 돌지 않는다

`sample=0.05` 로 학습 행의 5% 만 써서 데이터 부족 모델을 만들었다.

```
학습 281행 (2022-01-10 ~ 2022-04-05), 평가 300행 (2026-08-21 ~ 2026-11-18)
게이트 탈락
- 데이터: samsung 의 학습 행이 56개다 (기준 200개 이상)
- 데이터: kakao 의 학습 행이 56개다 (기준 200개 이상)
- 데이터: sm 의 학습 행이 56개다 (기준 200개 이상)
- 데이터: hybe 의 학습 행이 57개다 (기준 200개 이상)
- 데이터: skhynix 의 학습 행이 56개다 (기준 200개 이상)
- 기준선: 모델의 logloss 0.7107 가 기준선 0.6935 보다 나쁘다
- 현재 모델: 새 모델의 logloss 0.7107 가 현재 모델 m20261123-2 의 0.6980 보다 나쁘다
기준선 검사: 모델 0.7107  기준선 0.6935  (허용 0.7035 이하)
현재 모델 검사: 모델 0.7107  현재(m20261123-2) 0.6980  (허용 0.7030 이하)
```

세 검사(데이터 · 기준선 · 현재 모델) 모두에 걸렸다. train 이 실패해 promote 는 건너뛰었고 서버의 모델은 바뀌지 않았다.

## 찍을 화면

- 실행 1 · 3 · 4 의 요약 화면 (Job 그림에 성공 · 실패 · 건너뜀이 보인다)

- 실행 4 의 train → `task model` 로그 (탈락 이유)
